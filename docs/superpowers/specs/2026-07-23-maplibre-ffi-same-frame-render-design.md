# MapLibre dart:ffi Same-Frame Render — Design

**Date:** 2026-07-23
**Branch:** `maplibre-perf`
**Builds on:** `2026-07-23-maplibre-latency-bundle-design.md` (device-validated; see its
"Device validation results" section)

## Problem

The latency bundle fixed 120Hz: idle renders zero frames, push latency dropped from
17–25ms to 2.4–5ms, fling stutter is gone. Low Power Mode (60Hz) still stutters and
trails the viewport on fling-decel. The root cause is architectural, not a tuning gap:

The current pipeline **estimates, across an async boundary, what a shared buffer will
contain when another thread reads it**. `_rendered` is stamped at send time; the native
handler renders into the single shared CVPixelBuffer at an arbitrary point mid-frame;
the raster thread samples that buffer whenever it composites. When the estimate loses
the race — more often at 60Hz, where throttled pushes take 4–7ms — the composite pairs
new texture content with a transform computed for older content, and each loss is one
full frame of pan error. Every mitigation so far (send-time stamping, the 7ms
suppression window) patches the estimate; the residual error resurfaces wherever timing
degrades.

Two things eliminate the estimate instead of patching it:

1. **Same-frame render (dart:ffi):** render the texture synchronously inside the build
   that uses it. Texture content ≡ current camera by construction; there is nothing to
   estimate. Budget-wise it fits: measured render is ~2.5ms avg inside an 8.3ms frame.
2. **Immutable presentation (buffer ring):** the raster thread must only ever sample
   buffers that are complete and will not be written again while in use. A ring of
   3 buffers with an atomic front-buffer publish gives swapchain semantics; the race
   dies by construction even when the raster thread runs late (the low-power regime).

This design does both.

## Goal

Replace the method-channel camera hot path with direct `dart:ffi` calls into
`maplibre_native_c`, rendering synchronously during build, presenting through a
3-buffer ring. Success criteria, on the iPhone 14 Pro harness:

- Low Power Mode fling-decel smoothness at parity with the 120Hz experience.
- Idle still renders zero frames (gate behavior preserved).
- Inline render cost visible in diagnostics and within frame budget (no new 120Hz jank).

## Decisions (with alternatives rejected)

- **Replace the channel hot path outright.** No runtime toggle between channel and FFI
  paths; git history is the A/B baseline. The channel survives only for the cold path
  (texture creation/registration, dispose). *Rejected: keeping both toggleable* — two
  stamping models alive in the widget, double review surface.
- **FFI + buffer ring in one plan** (two device-measurable phases). *Rejected: FFI
  only, single buffer* — kills latency and estimation but leaves a narrow overlap race
  when raster runs late, exactly the regime being fixed. *Rejected: buffer ring on the
  channel path without FFI* — fixes the race but keeps 4–7ms throttled push latency and
  the estimation architecture.
- **Blit-based presentation, not target rotation.** The C API allows one live render
  session per map with a fixed borrowed target (`mln_metal_borrowed_texture_attach`);
  per-frame detach/re-attach is unknown-cost renderer churn. The session renders into
  one fixed back buffer; a Metal blit (~0.1–0.3ms, memory-bandwidth bound) copies it
  into the ring slot being published. *Rejected: owned-texture sessions*
  (`mln_metal_owned_texture_acquire_frame`) — they hand back raw `MTLTexture`s, which
  `FlutterTexture.copyPixelBuffer` cannot consume, and forbid rendering while a frame
  is acquired.
- **Runtime moves wholly to the Dart UI thread.** The C API is owner-thread affine
  (`MLN_STATUS_WRONG_THREAD` from any other thread), so creation, event pump, render,
  and teardown all migrate together. The CADisplayLink becomes a widget `Ticker` with
  the same gate logic. This is enforced by the API, not by convention.

## Architecture

### New: `packages/flutter_map_maplibre/lib/src/ffi/`

- `maplibre_bindings.dart` — ffigen output over the vendored xcframework headers
  (`ios/MaplibreNativeC.xcframework/ios-arm64/Headers/maplibre_native_c.h`).
  Generated by a committed `ffigen.yaml`; the generated file is committed too (codegen
  is a dev-time step, not a build step). Symbols resolve via
  `DynamicLibrary.process()`.
- `maplibre_renderer.dart` — the Dart port of `MLNBridge.m`, owning the native handles
  (`mln_runtime`, `mln_map`, `mln_render_session`) and the logic that today lives in
  ObjC: event pump with sticky `updateAvailable`, `needsRepaint` tracking, gated
  render, camera jump + render, style swap, stats counters (renderMs EMA/max/steady,
  cameraRenders, linkRenders, skippedTicks, idleEvents, drawCalls). Exposed to the
  widget behind an abstract interface so tests inject a fake and never touch FFI.

### Shrunk: native side

- `MLNBridge.m/h` — deleted (fully ported to Dart).
- `MapLibreProbe.swift` → `TexturePresenter` responsibility: create one plain
  `MTLTexture` back buffer (render-target usage; the session's fixed borrowed target)
  and a ring of 3 IOSurface-backed CVPixelBuffer+`MTLTexture` pairs (blit
  destinations); implement `FlutterTexture.copyPixelBuffer` returning the current
  front buffer, retained; keep everything alive until dispose.
- A C-callable presentation function exported for FFI, e.g.
  `int64_t fmm_present(int64_t presenterId)`: blit back → next ring slot
  (command buffer, `waitUntilCompleted`), atomically publish that slot as front,
  call `textureFrameAvailable`, return a status/blit-time payload. Called from the
  UI thread immediately after a successful render.
- A symbol-keeper compilation unit: an `__attribute__((used))` pointer table
  referencing every `mln_*` symbol Dart calls, so they survive dead-stripping.
- The method channel keeps only: `createTextures` (returns `textureId`, the back
  buffer `MTLTexture` address as int64, and the presenter id) and `disposeTextures`.
  `runMap`/`setCamera`/`setStyle`/`mapDiagnostics` handlers are deleted.

### Rewired: `MapLibreBasemap` widget

- `_pushCamera`, `_rendered`, `_pendingCamera`, `_pushInFlight`, send-time stamping,
  rollback, and `pushToTextureMs` are deleted.
- Build calls `renderer.render(camera)` synchronously: `mln_map_jump_to` +
  `mln_map_request_repaint` + event pump + `mln_render_session_render_update` +
  `fmm_present()`. On success the widget draws the texture at **identity** transform.
- On failure (render or present), nothing is published; the front buffer still shows
  `renderer.lastRenderedCamera` — the renderer's ground truth, not an estimate — and
  the widget applies `residualTransform(rendered: lastRenderedCamera, current: camera)`
  and retries on the next build. `residualTransform` and `camera_conventions.dart` are
  unchanged.
- A `Ticker` replaces the CADisplayLink for idle animations (tile fades, transitions):
  each tick pumps events and renders+presents only when `updateAvailable ||
  needsRepaint`, and skips if build already rendered this frame (a per-frame flag, not
  a wall-clock window — the 7ms suppression heuristic dies with the race).
- Creation flow: layout → channel `createTextures` → Dart creates runtime/map/session
  via FFI on the UI thread, attaching the back buffer address. Dispose: Dart destroys
  session/map/runtime via FFI, then channel `disposeTextures`. This ordering keeps
  every `mln_*` call on the owner thread. Session recreate resets the renderer's
  `lastRenderedCamera`, which retires the earlier follow-up about `_create` not
  resetting `_rendered`.

## Frame flow (steady state, one thread)

1. Gesture moves the `flutter_map` camera → `MapLibreBasemap.build` runs.
2. `renderer.render(camera)`: jump_to → request_repaint → pump events → render_update
   (blocks ~2.5ms incl. GPU; the FFI waits for completion internally) → on OK,
   `fmm_present()` blits into ring slot *i* and publishes it.
3. Build returns `Texture` at identity transform. The frame is submitted; whenever the
   raster thread composites — even late — it samples ring slot *i*, which is complete
   and immutable while retained.
4. Ticker tick (same frame, after build): sees the per-frame rendered flag, skips.
   Idle frames: no camera change → build doesn't render; ticker renders only on
   update/repaint events; a stationary, settled map renders zero frames.

## Risks and probes (Task 1, before any porting)

1. **Symbol visibility** — the archive is static (`libmln-stripped.a`); dead-stripping
   and app-binary symbol stripping can hide `mln_*` from `dlsym`. Probe: one trivial
   FFI call (`mln_runtime_options_default`) in a **profile** build on device, with the
   keeper table in place. Fallback knobs, in order: `STRIP_STYLE=non-global` via
   podspec `user_target_xcconfig`; rebuilding the xcframework as a dylib.
2. **`textureFrameAvailable` from the UI thread** — must reach the engine in time for
   this frame's raster pass. Probe: present alternating solid-color frames from the UI
   thread and verify same-frame pickup on device; if a main-queue hop turns out to be
   required, measure whether the async dispatch still lands before raster.
3. **Inline render budget** — ~2.5ms avg is fine; 11ms max spikes will blow the
   occasional frame. Accepted for now (spikes are rare and were previously paid on the
   platform thread in parallel). If the device shows new 120Hz jank, the escape hatch
   is a skip-and-fallback guard: skip the inline render when the previous render
   exceeded a threshold, and lean on the (already present) failure path's residual
   transform for that frame. Not built until measured.

## Diagnostics

Same overlay and MLNDIAG line, resourced: `renderMsInline` (EMA of the in-build render,
replacing `pushToTextureMs`), `blitMs` (from `fmm_present`), plus the ported counters
(`renderMsAvgSteady/MaxSteady/Last`, `cameraRenders`, `linkRenders`, `skippedTicks`,
`idleEvents`, `needsRepaint`, `drawCalls`). Phase chips and the log-mute behavior are
unchanged.

## Testing

- **Widget tests** (rewrite of `maplibre_basemap_test.dart`): against the fake
  renderer — build renders with the current camera exactly once per frame; identity
  transform on success; honest transform from `lastRenderedCamera` + retry on failure;
  ticker gating (no render when idle, render on update events, skip when build already
  rendered).
- **Renderer unit tests** where logic is pure Dart (gate conditions, stats
  accounting) with the FFI layer stubbed at the bindings boundary.
- **FFI layer**: device-validated only (host unit tests cannot load the library).
  Probes in Task 1; full three-phase harness (idle / fling / low-power) at the end,
  results appended to this spec.

## Out of scope

- Android. The Dart renderer is platform-neutral by construction; only the
  presentation shim is Metal-specific. Vulkan/GL shims come with the Android port.
- Over-render margin, prediction, adaptive suppression windows — all retired or
  superseded by this architecture.
- Upstreaming changes to maplibre-native-ffi (e.g. removing the internal GPU wait).
  PR maplibre-native-ffi#187 (sargunv's ffigen bindings) is prior art for the
  bindings setup, not a dependency.

## Device validation results (2026-07-23, iPhone 14 Pro, profile)

All three phases PASS; the success criterion is met.

- **Idle:** counters frozen (frames/cam/link static across samples), skippedTicks
  advancing ~120/s, needsRepaint false — a settled map renders zero frames.
- **Fling (120Hz):** renderMsInline 2.2–4.7ms, blitMs 1.0–1.9ms, camera renders
  tracking the gesture. In budget; no desync.
- **Low Power (60Hz):** renderMsInline 4–6ms (one 9.9ms spike at the mode switch),
  blitMs 1.6–3.3ms — inside the 16.7ms budget.

Human verdict: remaining stutter is ordinary Flutter frame pacing and is
**synchronized** — markers, polylines, and basemap move as one surface; nothing
leads or trails, in any power mode. Low Power increases stutter uniformly without
desynchronizing. Quote: "the icons on top of the map ... never lag or are never
ahead of the map behind it, so it feels natural ... I would say this is perfect."
The composite race and the estimation error are gone, by construction and now by
measurement. Checkpoints A and B are thereby re-confirmed on device in profile mode.

### New finding: bottom-sheet resize flashes the map

Resizing the bottom sheet triggers a full session recreate (borrowed-texture
sessions cannot resize), and the widget shows nothing between disposing the old
texture and the new session's first frame — the map goes transparent, then
re-renders. The channel-era code hid this behind a bug: `_creating` was never
reset, so recreation silently never happened and a stale-size texture was clipped
instead. Fix direction: debounce recreation until the size settles, and keep the
old texture on screen (plugin holds presenters by id; dispose the old one only
after the replacement session's first frame) so the swap shows a brief frozen
frame instead of transparency.
